Несущие контуры

не список сервисов, а роль каждого слоя в устойчивости системы

01

Continuity / Steward

Операционная истина

Текущее состояние объектов, события, внимание, владельцы хода, обязательства и блокеры. Остальные слои не должны создавать второй источник истины.

СОСТОЯНИЕ —
02

Долговечность артефактов

Байты, подтверждение записи и обратное чтение

Файл считается сохранённым не потому, что его «отправили», а потому что подтверждены запись, долговечное местоположение и возможность прочитать его обратно.

СОСТОЯНИЕ —
03

Путь одобрения Основателя

Изменение полномочий только через явное решение

Предложение изменения не равно разрешению. Действия, требующие уровня Основателя, остаются заблокированными до явного одобрения.

СОСТОЯНИЕ —
04

Целостность отображения

Экран не может быть «зелёным» при недоступном источнике

Панель обязана различать живые, устаревшие, деградированные и недоступные данные и не подменять отсутствие источника старым спокойным состоянием.

Операции что из уже утверждённого реально исполняется, кто держит мяч, что было сделано и где исполнение остановилось.

Что не переносим из старой страницы

правдоподобные operational-метрики без источника больше не выдаются за живое состояние

Нет выдуманной очереди задач 27 задач и «6 готовы» не показываются, пока нет реального поля именно с таким смыслом.
Нет фиктивных gates Количество gates не выводится из маршрутов и не считается Панелью самостоятельно.
Нет fake throughput «39 ходов за сутки» и median cycle не существуют без поддерживающего источника.
Нет декоративных PASS/RUN Исполнение считается успешным только после реального события или подтверждённого результата.
Текущий технический факт: старый Operations live-модуль получает только Orchestrator summary / metrics / routes. Этого достаточно для некоторых чисел маршрутов, но недостаточно для полноценной страницы исполнения. Поэтому G11 не маскирует Orchestrator routes под отдельную операционную истину.

Что именно принадлежит Реестру

граница нужна, чтобы Реестр не стал ещё одной копией всей системы

Реестр владеет Object ID, идентичностью, типом объекта, каноническим владением и тем, существует ли объект как признанная системная сущность.
Continuity владеет операционным состоянием, событиями, движением, блокерами, вниманием и текущими обязательствами.
Владеющая ветка владеет смыслом объекта, исследовательскими или продуктовыми решениями и интерпретацией результатов.
Панель только показывает нормализованную проекцию. Она не назначает новый Object ID и не создаёт второй источник истины.
Правило идентичности: если Object ID неизвестен — показываем «не определён», а не выбираем ближайший похожий ID. Это особенно важно для Testing Department и Path Legibility.

Публикационный путь

это роли артефакта, а не обязательная линейная судьба каждого файла

MASTER Рабочая версия текущая авторитетная рабочая версия в рамках своей ветки
→
FROZEN Зафиксированная версия снимок, который нельзя тихо переписать после проверки или решения
→
SUBMITTED Отправленная версия точно тот артефакт, который был передан внешней стороне
→
PUBLIC Публичная версия опубликованный артефакт с проверяемой связью с его происхождением
Панель не считает количества MASTER / FROZEN / SUBMITTED / PUBLIC, пока отдельный источник не отдаёт эти состояния. И не предполагает, что каждый рабочий файл обязан пройти все четыре роли.

Граница ответственности

Документы показывают состояние артефактов, но не становятся новым хранилищем истины

Artifact Durability отвечает за реальное сохранение, подтверждение записи и проверяемость байтов.
Continuity / Registry дают идентичность объекта, события и канонический контекст, к которому относится артефакт.
Владеющая ветка решает смысл документа и когда создаётся master, frozen, submitted или public артефакт.
Панель читает проекцию, показывает очередь и происхождение; сама не переписывает файлы и не повышает их статус.
Ключевое правило: durable ≠ canonical, frozen ≠ public, submitted ≠ accepted, а наличие файла ≠ подтверждённая связь с объектом.

Что Диагностика не делает

это инженерный экран только для чтения, а не скрытая панель управления системой

Не меняет настройки источниковконфигурация runtime и deployment остаётся у владеющего сервиса / Клима.
Не перезапускает сервисыможно показать рекомендуемый recovery path, но не давать скрытую write-authority.
Не хранит секретыникаких токенов, ключей, credential values или приватных инфраструктурных деталей.
Не скрывает отказлюбая потеря источника должна быть видна на затронутой странице, а не только здесь.
Главное правило: Диагностика объясняет причину деградации. Она не имеет права делать остальные экраны «зелёными» при отсутствии доказанного текущее состояние.
